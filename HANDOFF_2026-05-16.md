## 5. ARCHITECTURE SUMMARY

**Auth:** Supabase Auth, `flowType: 'pkce'`. `/auth` (customer) + `/creator-auth` (creator) entry. Confirmation link → `/auth/callback?code=…` → exchanges via `code_verifier` in localStorage → routes by intent (`creator` → `/creator-application-pending`, else `/dashboard`). Stale-link `#error=…` rendered by `<AuthErrorBanner />` with Resend CTA.

**Onboarding:** customer signup → email confirm → `/dashboard`. Creator path: signup at `/creator-auth` Apply → `submit_creator_application` RPC writes `creator_verifications` (status=pending) → admin reviews `/admin` → `admin_approve_creator_application` RPC sets `user_roles.role='creator'` + `profiles.role='creator'` + flips verification → creator should land in `/creator-onboarding` (B4 — currently lands on `/dashboard`).

**Wallet:** balance lives in `profiles.wallet_balance` (NOT a `wallets` table). All writes via SECURITY DEFINER RPCs: `send_paid_message`, `purchase_subscription`, `unlock_content`, `use_subscription_message`, `send_bundle_message`, `process_all_subscription_renewals`. Deposits via Stripe Checkout → `stripe-webhook`. UI live update via `wallet-balance-update` CustomEvent.

**Subscriptions:** `subscription_tiers` (creator_id, name, price, billing_interval, free_messages_per_month, unlimited_messages). `creator_subscriptions` (customer_id, creator_id, tier_id, status, current_period_end). `subscription_message_usage` for free-message tracking. Renewal: pg_cron `renew-wallet-subscriptions` daily 02:00 UTC → `process_all_subscription_renewals()` with `FOR UPDATE SKIP LOCKED`. Insufficient funds → status `past_due`.

**Unlockables:** `unlockables` (public Storage bucket). `unlock_content(p_unlockable_id, p_creator_id, p_price)` atomic: lock row, idempotent check on `unlocked_by` array, balance check, deduct wallet, append user_id, record `wallet_transactions` + `transactions` + `platform_fees`.

**Uploads:** three public buckets — `avatars`, `unlockables`, `voice-messages`. Video size limit set via Supabase dashboard (500 MB), not migration.

**Messaging:** `messages` RLS allows SELECT for participants. INSERT only via SECURITY DEFINER RPCs after `20260514100002`. Conversations created SELECT-then-INSERT (RLS-safe). First-send race fixed via `convOverride` param. Realtime via `postgres_changes`; unlockable inserts trigger refetch.

**Admin approval:** SECURITY DEFINER RPCs `admin_approve_creator_application` + `admin_reject_creator_application` (atomic across user_roles + profiles.role + creator_verifications). Bypass column-level REVOKE on `profiles.role`.

**Key RPCs:** `submit_creator_application`, `admin_approve_creator_application`, `admin_reject_creator_application`, `send_paid_message`, `send_first_three_free_message`, `send_bundle_message`, `use_subscription_message`, `purchase_subscription`, `process_all_subscription_renewals`, `unlock_content`.

**Critical RLS assumption:** Policies do NOT replace GRANTs. A correct policy can still 403 if the underlying GRANT is missing. Watch for this pattern (it bit us on `subscription_tiers` and `creator_verifications`). When adding a new RLS policy, always confirm `GRANT SELECT/INSERT/UPDATE` on the table for `authenticated`.

**Column-level protection:** `profiles.wallet_balance` and `profiles.role` have UPDATE REVOKEd at column level — only SECURITY DEFINER RPCs can write.
